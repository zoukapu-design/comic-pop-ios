# ムビコマ｜同一シーンの演出カード合成・物語品質改修（2026-11-08）

## 実機スクリーンショットで確認した問題
- 5カードのうち「ドラマティック」と「恐怖」が同じ時間位置に挿されていたにもかかわらず、現行コードでは `MangaPin` 1枚につき1コマを生成したため、意味のほとんど同じ2コマになった。
- 作品一覧で「2ページ」と表示され、1ページ目は4コマ、2ページ目は料理の1コマ。スクリーンショットの2画像がまったく同一というより、**シーン/カード/コマの対応とページ表示に不自然さ**がある。
- 「1コマ=動画の画像を漫画に加工」ではなく「**1シーンをどのように演出するかがカードの役割**」という根本仕様へ修正する。
- 画像モデルの参照写真優先・前コマ参照が、展開のない複製を促していた。映像内容の理解と構図・展開の変化を優先。

## 変更したアーキテクチャ
```
動画 + 挿入カード(時刻, 種類, メモ, セリフ)
  ↓
[1] 時間軸ソート・同時刻/近接カードのグループ化
  → 1.5秒以内を同じシーンと推定。同時刻の挿入順と全ID保持。
  ↓
[2] 1シーンに付く全カードの役割を合成
  例: ドラマティック＋恐怖 → 高揚感のある恐怖の演出を1コマに集約
  ↓
[3] 全シーンの動画フレームを番号付きコンタクトシートへ
  → ON: Cloudflare Llama4 Scoutの画像理解を用いて物語の脚本を1回生成
  → OFF/非対応: Visionの画像・字幕解析、任意の音声認識 + GLMの脚本
  → 失敗時は非対応と無料枠切れを区別。Cloudflare枠の追加利用はあり得る。
  ↓
[4] 物語の連続性/各カード役割/映像を統合したコマ単位の脚本
  → 同一の文章・場面が連続する脚本は画像作画前に拒否
  ↓
[5] FLUX画像生成（1つのシーンにつき1枚）
  → 元フレームは素材、脚本が絵の主導権を持つ
  → 人物・服の継続には前コマを追加参照
  → 同じ構図の複製は禁止・個別再生成は別構図を指示
  ↓
[6] 白黒は実際に全コマから色を抜いて統一
  → 日本語字幕・吹き出しはiOSのUIFontで付加
  ↓
[7] 4シーン/ページで分割保存、読書ビューアへ
```

## 5カードの期待結果
- 場面 0秒：導入
- 場面 40秒：**ドラマティック＋恐怖** ← カードは2枚だが**漫画は1コマ**
- 場面 75秒：リアクション
- 場面 115秒：オチ

→ **計5カード / 4漫画シーン / 1ページ**（描くコマ1〜4）。
同じ5枚でも5つの離れた場面なら**5漫画シーン / 2ページ**（ページ2の最初は**コマ5**）。
複数カードの情報は削除せず、タイムラインのカードマーカーも全枚数表示する。

## 実装したファイル
- `CardSceneGrouping.swift`: Foundationのみのシーン判定（代表時刻から最大1.5秒。推移的な無限結合は禁止）。
- `Models.swift`: `ScenePlan.scenes/renderPins/renderedPanelCount` を追加し、ページ数もシーン数で計算。
- `StudioStore.swift`: 画像・脚本生成、完了判定、再生成、保存をシーン単位に統一。メモ、演出、セリフは同じシーンの全カードから合成。
- `MangaStory.swift`、`MangaStoryServices.swift`：複合カードの日本語役割を脚本AIへ渡す、各カットの撮影距離と構図を変える、重複脚本を拒否。
- `MangaSceneContactSheet.swift`：選択した全シーンを番号付き画像でAIへ渡す。Cloudflare Llama4 Scoutが使えない場合は従来のGLMへフォールバック。
- `VideoAndAI.swift`：1シーンで複数の感情カードを融合・別構図再生成指示。
- `PopGenre.swift`、`PopReview.swift`：カード数と実際の描画シーン数を区別、重複に気付ける表示。
- `ComicRenderer.swift`：複合カードタイトルの表示領域を拡張、コマ番号を全ページ通し番号で表示。
- `tests/modelTests.swift`：同時刻ドラマ+恐怖の1シーン合成、独立5シーン2ページ、独立12シーン3ページ、同じ時刻のカードID維持。
- `tests/mangaStoryTests.swift`：重複ストーリー拒否、両方の演出とユーザー入力セリフが1コマに残ることを検証。

## チェック結果と未検証事項
- Foundationのみで独立可能なSwiftのシーングルーピングをLinux Swift 6で実行：**PASS**（同時刻合成、5別シーン分離、連続チェーン結合防止）。
- Swiftの `ScenePlan` の格納プロパティ初期化とキーパスのtypecheck：**PASS**（Linuxの代表コード）。
- GitHub Actionsはジョブが3秒でfailureとなりログが404で取得不能。**CI成功とは言えない**。今回の追加コードをCodemagic/iPhoneでコンパイル・実行したこともまだない。
- Cloudflareの実アカウントAPI呼び出し（Vision・GLM・FLUX）の実動作／容量制限は未検証。Cloudflareの「無料枠内で必ず動く」とは宣言しない。
- 動画の音声・字幕の誤認識、画像生成時の文字の描き込み残り、人体・構図の不整合などは次ビルドで実例検証が必要。
- SceneGrouping 1.5秒は初期の簡易推定。動画の中で同じシーンが時間をまたいで続く場合、将来は映像内容の相似・手動統合・場面切替検出で判断を補強する。

## 一発ビルド時の確認
1. `feat/movikoma-rex-reference-ui` の `ios-unsigned-check` を1回（コンパイルのみ）実施し、`ios-diagnostics.txt` からエラーを解消。
2. `ios-testflight-upload` を署名済み検証時のみ手動実行。
3. テスト動画で同時刻に2カードを刺す→生成前画面に「カード5枚 → 4シーン」が見える。
4. 生成レビューでは「ドラマティック＋恐怖」が1コマだけ存在し、怖さ＋盛り上がりの両方を感じられるか確認。
5. 別々の5場面なら2ページが生成され、ページ2にはコマ5が表示され、読書ビューアで全ページ読める。
6. 白黒指定でも途中だけカラーにならない。前コマと似た構図はレビューに警告が出る。
7. 最も重要：漫画として**導入／事件／リアクション／結末**が成立しているか、字幕・声・カードの役割に矛盾がないかを人が見て厳しく評価する。
